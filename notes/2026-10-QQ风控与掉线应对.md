# 2026-10 QQ风控与掉线应对

关联：[[2026-10-AstrBot大肥鱼配置实录]]

## 实际掉线记录

| 时间 | 现象 | 处理 |
|---|---|---|
| 10-27 22:22 | 快速登录错误「你的用户身份已失效」 | 扫码 |
| 10-28 08:04 | 同上（NapCat 自动重试了两次） | 扫码 |
| 10-28 10:39 | 「账号已离线，正在重启 Worker」 | 未及时处理，离线 9 小时 |

**24 小时内被踢 3 次**。

## 根因判断

风控权重排序（根据现象推断）：

1. **账号本身**——小号 <BOT_QQ>，等级低、好友少、无实名 → 最大嫌疑
2. **行为模式**——频繁重启容器、反复登录（一天扫三次码本身就是异常信号）
3. IP——家宽 NAS，稳定，不是问题
4. **协议实现**——NapCat 跑的是腾讯官方 NTQQ 的 Linux 版（有官方签名），很多人在用，这套本身不是雷

**Linux vs Windows 不影响**：换系统只换了壳，账号权重/IP/行为记录全不变。而且 NAS 8G 内存跑 Windows 虚拟机不现实。

## 快速登录配置（已做）

容器环境变量：
```
NAPCAT_QUICK_PASSWORD=***   # 已配
ACCOUNT=<BOT_QQ>
restart=always
```

WS 侧：`enableHeart: true`、`reconnectInterval: 3000`（断线 3 秒重连）。

## 三种掉线的不同结局

| 掉线类型 | 密码能否自救 |
|---|---|
| 容器崩 / NAS 重启 | ✅ restart=always |
| WS 断开 | ✅ 3 秒自动重连 |
| QQ 普通掉线（登录态失效） | ✅ 密码自动重登 |
| **腾讯风控（身份已失效）** | ❌ 密码会触发**短信验证**，等于把扫码换成收短信，还是要人 |

所以风控型掉线**必须人工**，密码只对普通掉线有用。

## 诊断速查

```bash
# 在线吗
sudo ss -tn | grep 6199                    # 有连接=在线
sudo docker logs --tail 30 napcat | grep -aiE "登录|离线|ErrCode"

# 看到什么状态做什么
# 「正在快速登录」→ 等 30 秒，它在自救
# 「需要扫码 / 短信验证」→ 必须人工
```

NapCat WebUI（实时二维码）：`http://<NAS_IP>:6099/webui?token=<见配置>`

## 应对方案（按性价比）

1. **养号（最有效）**：连续 3~5 天不折腾——不重启容器、不改资料、不加好友/群、不发东西
2. **用官方 QQ 客户端登录几次**：让腾讯看到真人在用
3. **换老号**：有等级/好友/实名的号，立刻就好
4. **QQ 官方 Bot API**：不掉线不风控，代价是不能主动找人、插件大部分不可用
5. **换 Windows**：基本没用，别折腾
